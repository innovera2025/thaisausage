# สถานะระบบ ณ 30 กันยายน 2026 — สำหรับเริ่มงานต่อ

Environment: VPS `krs-cloud` (`72.61.120.22`), `/opt/thaisausage`
Commit ล่าสุด: `4c98711`

## ระบบเดินเองครบทั้งสองทิศทางแล้ว

| ทิศทาง | สถานะ |
|---|---|
| SO: ERP → eVRP | ✅ กวาดทุก 60 วินาที ทุกบริษัท สูงสุด 100 ใบต่อรอบ |
| DO: eVRP → ERP | ✅ `do_write.enabled = true` เขียนทันทีที่ callback เข้ามา |
| แก้ DO ที่เขียนแล้ว | พร้อมใช้ แต่ปิดอยู่ (`do_write.update_enabled = false`) |

ตัวเลขล่าสุด: SO ส่งสำเร็จ 933 ใบ · DO เข้า ERP 5 ใบ (`TransactionNo` 900001–900005)

## สิ่งที่ต้องรู้ก่อนแตะอะไร

1. **`assemble_config.py` ต้องใส่ `--enable-do-write` ทุกครั้ง** ไม่งั้นโหมดเขียนอัตโนมัติจะปิดเงียบๆ
2. **แก้ `config/local.json` แล้วต้อง `up -d --force-recreate`** — `up -d` เฉยๆ ไม่โหลด config ใหม่
   ถ้าโค้ดไม่เปลี่ยน
3. **รัน `preflight` หลังแก้ SQL ทุกครั้งก่อนปล่อยให้กวาด** — เคยเพิ่มคอลัมน์ที่ไม่มีอยู่จริง
   (`VatType` ที่ชื่อจริงคือ `IncludeVat`) แล้ว SO หยุดไหลไปกว่าชั่วโมงโดยไม่มีใครรู้
4. **ไม่สร้าง DO ทดสอบเอง** — เจ้าของงานสั่งให้ใช้เฉพาะ DO จริงจาก eVRP
5. **ทุกคำสั่งบน VPS เจ้าของงานเป็นคนรัน** ผู้ช่วยเตรียมคำสั่งให้เท่านั้น

## สองอย่างที่ไม่ลองใหม่อัตโนมัติ

- **SO ที่ eVRP ปฏิเสธ** ติด `needs_review` ต้องล้าง claim เมื่อ eVRP ตั้ง master เสร็จ
  (ล้างไปแล้วครั้งหนึ่ง 496 ใบ เมื่อ 30 ก.ย. เพื่อให้ส่งซ้ำ)
- **DO ที่เขียนไม่สำเร็จ** ติด `failed` หรือ `pending` ต้องตรวจ ERP ก่อนสั่งเขียนใหม่

ดูทั้งสองอย่างได้จาก `python -m thaisausage.status --days 1` หัวข้อ "รายการที่ต้องให้คนดู"

## รอทีมอื่น

| เรื่อง | ใคร |
|---|---|
| ตั้ง master 358 รายการ (จุดส่ง 312 · ลูกค้า 45 · Route 1) | eVRP — ส่งเอกสารให้แล้ว เริ่มทำแล้ว |
| `DlvCode` ควรเก็บอะไร (`nchar(10)` แต่ eVRP ส่งรหัสลูกค้า 14 ตัว — ตอนนี้เว้นว่าง) | ERP |
| `LocationCode` ที่ได้มาเป็นรหัส hub ของ eVRP ต้องแปลงไหม | ERP |
| `TotalAmount` เป็นยอดเต็ม SO ไม่ใช่ยอดที่ส่งจริง — ต้องการยอดไหน | ERP |
| บัญชี SQL ที่ `INSERT` ได้เฉพาะสองตาราง แทน `sa` | ERP/DBA |
| ใบรับรอง SSL ของ SQL Server (ตอนนี้ `TrustServerCertificate=yes`) | ERP/DBA |

เจ้าของงานแจ้งว่าสามข้อแรกจะจัดการเอง และสั่งให้เปิดใช้งานจริงไปก่อนโดยไม่ต้องรอ

- เปลี่ยน `THAISAUSAGE_API_KEY` และ `ERP_SQL_PASSWORD` — ทั้งคู่เคยปรากฏในแชท
- `rm -f /opt/thaisausage/.env.bak.*` — ไฟล์สำรองมีรหัสผ่าน
- สองใบที่จงใจไม่เขียน: `DO2609040004` (ราคาเป็น 0 ทุกบรรทัด) และ `DO2609040006-COD`
  (ไม่มี `header`/`details` เป็นข้อความแจ้งรับเงิน ยังไม่มีที่ทางใน ERP)
- `SO-L2609-1709` ผลรวมบรรทัดไม่เท่าหัวเอกสาร ERP (2,032 vs 2,287) ยังไม่ได้ถามฝ่ายขาย

## เครื่องมือที่มี

| คำสั่ง | ทำอะไร |
|---|---|
| `status --days N` | สรุปว่าส่งไปเท่าไร ค้างอะไร อะไรต้องให้คนดู |
| `preflight` | ตรวจ SQL และข้อมูลก่อนส่ง — รันหลังแก้ config ทุกครั้ง |
| `fit_do --receipt-id X` | เทียบค่าทุกคอลัมน์กับความกว้างจริงใน ERP ก่อนเขียน |
| `write_do --receipt-id X [--commit]` | ซ้อมเขียน / เขียนจริงทีละใบ |
| `verify_do --transaction-no N` | อ่านเอกสารกลับจาก ERP มาเทียบกับที่ส่ง |
| `rejection_report` | รวมข้อความปฏิเสธจาก eVRP เป็นเอกสารให้ทีมเขา |
| `discover` | สำรวจ schema ของ ERP |
| `deploy/assemble_config.py [--check] [--enable-do-write]` | ประกอบ config จาก git |
